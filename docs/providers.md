# Providers

Every provider implements one interface (`packages/providers/src/types.ts`) and normalises into the shared `Resource` model: `type` (`repository | package | paper | documentation | collection | website`), canonical URL, provider, retrieval timestamp + freshness, available metadata, and **evidence references** with status. A paper, a package, a doc page and a repository are never the same object.

Also used (not discovery providers): **OSV.dev** (`/v1/querybatch`, `/v1/vulns/{id}`) for advisories; the npm registry for deprecation/latest version.

## Etiquette & safety

- HTTPS only; no embedded credentials; private/loopback/link-local/metadata addresses blocked (also after DNS resolution and on every redirect); redirects ≤ 3 and credentials stripped on cross-host redirects; 12 s default timeout (per-provider override); 5 MB response cap; per-provider local rate limiting; descriptive `User-Agent` with no personal data.
- Tokens are sent only to the provider they belong to and are redacted from logs, errors and outputs.
- Failures never fail a whole search: a failing provider yields a warning, stale cache is served when available, and a hard-failing provider is skipped for the rest of that run (circuit breaker).

## Adding a provider

Implement `Provider` (`id, name, description, resourceTypes, auth, docsUrl, limitations, defaultSearch, availability(), search(), get?()`), build results with `makeResource()` (attaches provenance + freshness), register it in `ProviderRegistry`, and add fixture-based tests in `tests/unit/providers.test.ts`. Document live limitations honestly.
