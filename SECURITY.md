# Security policy

## Reporting a vulnerability

Please report suspected vulnerabilities **privately** via GitHub's "Report a vulnerability" (Security → Advisories) on this repository, with reproduction steps and impact. Do not open public issues for vulnerabilities. We aim to acknowledge within 7 days. There is no bug bounty.

## Supported versions

Only the latest released minor version receives security fixes (project is pre-1.0).

## Threat model & controls

Repo Scout processes **untrusted third-party data** (repository metadata, READMEs, packages, papers, web results) on a developer machine and feeds summaries to AI agents. Assets: the developer's files and credentials, the agent's behaviour, the local database.

| Threat                                          | Control (code)                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ----------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Prompt injection via README/descriptions/topics | Output is data-only: control/zero-width/bidi characters and HTML comments stripped, length-capped (`sanitizeText`); injection-like phrases flagged (`scanForPromptInjection`) and surfaced as security indicators; every tool response carries an `untrustedContentNotice`; MCP server `instructions`, the skill and generated plans repeat the rule; markdown output is escaped. Residual risk: an agent that ignores these instructions can still be manipulated — keep human approval on. |
| SSRF / internal network access                  | HTTPS-only, no embedded credentials, loopback/private/link-local/metadata ranges blocked by literal and after DNS resolution, re-validated on every redirect (≤ 3), credentials stripped on cross-host redirects (`SafeHttp`). Loopback is allowed _only_ for explicitly configured local services (Ollama, SearXNG). When an egress proxy is configured, DNS-level checks are delegated to the proxy.                                                                                       |
| Credential leakage                              | Tokens come from environment variables, are sent only to their provider, never stored by Repo Scout, redacted from logs/errors/outputs (`redact`, `redactDeep`), and `describeConfig` exposes booleans only. Config file is for non-secret settings. `.env*` is git-ignored; a test scans the repo for token patterns.                                                                                                                                                                       |
| Execution of untrusted code                     | Repo Scout never clones, builds, installs or runs repository code; manifests are parsed statically (`JSON.parse`/regex — no `eval`, no TOML/YAML executors). Install scripts are _reported_ (never run). `safeExec` is an allow-list (`git`, `node`), shell-less, with scrubbed environment and timeouts and is used only by `doctor`.                                                                                                                                                       |
| Unapproved filesystem/project changes           | The engine has no write path into user projects. Plans return five approval gates (clone, write, modify, install, execute) and hardened clone commands (`core.hooksPath=/dev/null`, `--depth 1`, `--no-recurse-submodules`, `core.symlinks=false`, scratch dir outside the project). `scout_clear_cache` requires `confirm=true`. CLI `-o` refuses to overwrite without `--force`.                                                                                                           |
| Path traversal / symlinks                       | `safeJoin` (traversal + symlink-escape checks), `isSafeRepoPath` filters tree entries, repository references validated by `parseRepoRef`, API paths URL-encoded.                                                                                                                                                                                                                                                                                                                             |
| Resource exhaustion                             | Response size caps, timeouts per provider, local token-bucket rate limiting, bounded concurrency, input length limits (task ≤ 8000 chars; manifests ≤ 500 KB).                                                                                                                                                                                                                                                                                                                               |
| Database corruption / concurrency               | WAL, busy timeout, immediate write transactions, transactional migrations with in-lock re-check, `0600` permissions, integrity check in `doctor`.                                                                                                                                                                                                                                                                                                                                            |
| Supply chain                                    | Three runtime dependencies (`@modelcontextprotocol/sdk`, `commander`, `zod`); `pnpm audit --prod` runs in CI; lockfile committed; no install scripts of our own.                                                                                                                                                                                                                                                                                                                             |

## What this tool does NOT do

It is **not** a security scanner or audit. "Security" scores are indicators from available metadata (OSV advisories for declared dependency versions, policy/lockfile presence, install-script presence). A clean result does not mean a project is safe. Licence output is not legal advice.

## Dependency audit

Run `pnpm audit --prod`. Latest result is recorded in [docs/development/validation-status.md](docs/development/validation-status.md).
